## 🐛 既知の問題

### 問題1: 日本語・マルチバイト文字の文字化け

**重要度**: 🔴 高
**影響範囲**: IT-J005, IT-J010-03
**ステータス**: 未修正（Java コード修正が必要）

#### 症状

日本語などのマルチバイト文字を暗号化・復号化すると文字化けが発生します。

```bash
Original: パスワード
Encrypted: esRhLjldxpK3HGmKajvhaBGkLlSGVaKZgQxUoN7Yf8PPKHTl/BU5PecgZyuddYJW
Decrypted: ???????????????
```

#### 原因

`util/EncDec.java` で文字列とバイト配列の変換時に文字エンコーディングを明示していないため、
プラットフォームのデフォルトエンコーディングが使用されます。

**問題箇所**:
```java
// util/EncDec.java Line 64
byte[] beforeEncBytes = before_enc.getBytes();  // ← デフォルトエンコーディング使用

// util/EncDec.java Line 95
return new String(afterDecBytes);  // ← デフォルトエンコーディング使用
```

#### 修正案

UTF-8を明示的に指定する必要があります：

```java
import java.nio.charset.StandardCharsets;

// Line 64
byte[] beforeEncBytes = before_enc.getBytes(StandardCharsets.UTF_8);

// Line 95
return new String(afterDecBytes, StandardCharsets.UTF_8);
```

#### 影響を受けるテスト

- ✗ IT-J005: マルチバイト文字（日本語）- 4/4テスト失敗
- ✗ IT-J010-03: 日本語を含むパスワード - 失敗

#### 回避策

現時点では、ASCII文字のみを使用したパスワードでテストを実施してください。

---

### 問題2: 不正なコマンド引数に対する終了コード

**重要度**: 🟡 中
**影響範囲**: IT-J007, IT-J010-05
**ステータス**: 未修正（Java コード修正が必要）

#### 症状

不正なコマンド引数を指定した場合、エラーメッセージは出力されますが、
**終了コード 0（成功）** を返します。

```bash
$ java -classpath util EncDec xxx "test"
Crypt Failed - [Argument Error xxx]
$ echo $?
0  # ← 本来は非0であるべき
```

#### 原因

`util/EncDec.java` の `main()` メソッドでエラー時に明示的に `System.exit(1)` を
呼んでいないため、正常終了として扱われます。

**問題箇所**:
```java
// util/EncDec.java Lines 24-27
if (argv.length != 2) {
    System.out.println("Crypt Failed - [Argument Number Error]");
    return;  // ← exit code 0で終了
}

// Lines 38-41
else {
    System.out.println("Crypt Failed - [Argument Error " + argv[0] + "]");
    return;  // ← exit code 0で終了
}
```

#### 修正案

エラー時に明示的に非0の終了コードを返す：

```java
if (argv.length != 2) {
    System.err.println("Crypt Failed - [Argument Number Error]");
    System.exit(1);  // ← 明示的にエラーコードを返す
}

else {
    System.err.println("Crypt Failed - [Argument Error " + argv[0] + "]");
    System.exit(1);
}
```

#### 影響を受けるテスト

- ✗ IT-J007: 不正なコマンド引数（異常系）- 1/2テスト失敗
- ✗ IT-J010-05: stderrのハンドリング - 失敗

#### 回避策

テストスクリプトで標準出力に "Error" または "Failed" が含まれているかを
確認することで、エラーを検出できます。

### 問題3: パフォーマンス目標未達成

**重要度**: ⚪ 低
**影響範囲**: IT-J010-10
**ステータス**: 設計上の制約（仕様変更が必要）

#### 症状

1回の暗号化/復号化操作に平均405.91msかかり、目標の100ms未満を達成できていません。

```
Total duration: 40591ms
Average per operation: 405.91ms
Expected: < 100ms
Received: 405.91ms
```

#### 原因

毎回 `java` コマンドを実行するため、JVMの起動オーバーヘッドが発生します。

**オーバーヘッドの内訳**:
- JVM起動: ~100-200ms
- クラスロード: ~50-100ms
- 実際の暗号化処理: ~10-20ms
- プロセス終了: ~50ms

#### 改善案

以下のいずれかの方法でパフォーマンスを改善できます：

1. **JNI (Java Native Interface) の使用**
   - Node.jsから直接Javaクラスを呼び出す
   - JVMを1度だけ起動し、再利用

2. **サーバープロセスとして実行**
   - Javaプロセスを常駐させる
   - ソケット通信またはパイプで連携

3. **目標値の調整**
   - 現実的な目標値（例: 500ms未満）に変更
   - JVM起動オーバーヘッドを考慮

#### 影響を受けるテスト

- ✗ IT-J010-10: パフォーマンス測定（100回）- 目標未達成

#### 回避策

**短期的**: テストの期待値を調整する（例: 500ms未満）

```javascript
// 修正案
expect(avgTime).toBeLessThan(500);  // 500ms未満に変更
```

**長期的**: アーキテクチャの見直し（JNI導入、サーバープロセス化）
