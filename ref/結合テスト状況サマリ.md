## Expected FAIL詳細

既知のバグにより、テストが失敗することが期待されるケース（`test.failing()`使用）:

| IT番号 | テストケース | 失敗理由 | バグ番号 | ファイル:行番号 |
|:------|:-----------|:---------|:---------|:---------------|
| IT-003-01 | groupIdで位置情報を取得できる | `sectionId`未定義変数エラー | BUG-001 | geolocation.js:120 |
| IT-007-01 | パスワード変更が正常に完了する | stderr判定ロジック逆転 | Bug #1-4 | user-info.js:502-513, 537-548 |
| IT-008-01 | 旧パスワード不一致時に適切にエラーが返る | stderr判定ロジック逆転 | Bug #1-4 | user-info.js:502-513, 537-548 |

### BUG-001詳細

**ファイル**: `models/geolocation.js`
**関数**: `getGeolocationByGroup(companyId, groupId)`
**行番号**: Line 120

**問題のコード**:
```javascript
async getGeolocationByGroup(companyId, groupId) {
  const query = SELECT_GELOCATION_GROUP_INJ
  const params = [
    companyId,
    companyId,
    sectionId,  // ← BUG: sectionId は未定義（引数はgroupId）
  ]
  // ...
}
```

**修正方法**: `sectionId` → `groupId`

**影響範囲**: グループIDによる位置情報取得が不可能（ReferenceErrorが発生）

### Bug #1-4詳細

**ファイル**: `models/user-info.js`
**関数**: `_checkOldPassword()`, `_changeToNewPassword()`
**行番号**: Lines 502-513, 537-548

**問題のコード**:
```javascript
const { stdout, stderr } = await exec(java_cmd)
if (hmUtil.isNullorUndefined(stderr)) {  // ← BUG: 判定が逆
  L.eLog.error('Java command error. ' + stderr)
  return false
}
```

**問題点**:
1. **stderr判定の逆転**: stderrが「ない」（正常時）にエラー判定している
2. **try-catch不足**: exec()失敗時にクラッシュの可能性

**修正方法**:
```javascript
try {
  const { stdout, stderr } = await exec(java_cmd)
  if (!hmUtil.isNullorUndefined(stderr)) {  // ← 否定を追加
    L.eLog.error('Java command error. ' + stderr)
    return false
  }
  // 正常処理
} catch (error) {
  L.eLog.error('Java command failed: ' + error.message)
  return false
}
```

**影響範囲**: パスワード変更機能が完全に動作不能

## Skip条件詳細

### 1. AWS環境チェック

**ファイル**: `aws-ssm.integration.test.js`
**Skip条件**: `environmentType !== '1'` (localhost環境)

- IT-004-03: SSM経由でDB接続ができる

## テスト実行手順（クイックスタート）

### 1. PostgreSQL起動

```bash
# Ubuntu/Debian
sudo systemctl start postgresql

# macOS
brew services start postgresql@14

# Docker
docker run -d --name heres-postgres -p 5432:5432 \
  -e POSTGRES_USER=imhereadmin \
  -e POSTGRES_PASSWORD=admin555 \
  -e POSTGRES_DB=imhere \
  postgres:14
```

### 2. データベース準備

```bash
# 接続確認
psql -h localhost -U imhereadmin -d imhere

# スキーマ作成（既存のSQLファイルがある場合）
psql -h localhost -U imhereadmin -d imhere -f schema/create_tables.sql

# テストデータ投入
psql -h localhost -U imhereadmin -d imhere -f ref/test-data-setup.sql
```

### 3. 環境チェック

```bash
bash ref/check-test-environment.sh
```

### 4. テスト実行

```bash
# 全テスト実行
bash ref/run-all-integration-tests.sh

# または、npm test直接実行
npm test -- --config=ref/jest.integration.config.js tests/integration/
```

## 既知の制約・制限事項

### 1. Expected FAILテスト

- BUG-001（geolocation.js:120）が修正されるまで、IT-003-01は失敗し続ける
- Bug #1-4（user-info.js）が修正されるまで、IT-007-01, IT-008-01は失敗し続ける
- バグ修正後は`test.failing()`を`test()`に変更すること

### 2. AWS環境テスト

- localhost環境では自動的にスキップされる
- AWS環境で実行する場合は`environmentType=1`を設定
- SSM Parameter Store、RDS PostgreSQLの事前設定が必要

### 3. テストデータ依存性

- 一部のテストは特定のテストデータ（user001, company001等）に依存
- テストデータが不在の場合は自動的にスキップされる
- `ref/test-data-setup.sql`で必要なデータを投入可能

### 4. Java EncDec依存性

- パスワード暗号化/復号化テストは`util/EncDec.class`が必要
- Javaが正常に動作しない場合、該当テストは失敗する
