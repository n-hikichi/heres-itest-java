# テスト用語定義

**作成日**: 2025-11-07
**目的**: テストレベルの用語を統一し、将来的な混乱を避けるため

---

## 📌 重要: 用語の統一

このプロジェクトでは、以下の用語を**厳密に区別**して使用します。

---

## 1. 結合テスト (Integration Test)

### 定義
複数のコンポーネント・モジュールを**結び合わせて**、それらの連携動作を検証するテスト。

### 英語表記
**Integration Test**

### 対象範囲
- 2つ以上のモジュール間のインターフェース
- モジュールとデータベース（PostgreSQL）の連携
- モジュールと外部コマンド（Java）の連携
- Express ミドルウェアチェーン
- APIエンドポイントとビジネスロジック層の連携

### 実装例
- `tests/integration/*.integration.test.js`
- IT-001 〜 IT-026 の各テストケース
- Jest を使用した自動テスト

### このプロジェクトでの使用例
```javascript
/**
 * IT-021: API認証結合テスト
 *
 * 複数モジュールの連携:
 * - models/api-auth.js (JWT生成)
 * - config/auth-config.js (秘密鍵)
 * - jsonwebtoken ライブラリ
 */
describe('IT-021: API認証結合テスト', () => {
  test('生成されたトークンが検証できる', () => {
    // 複数コンポーネントを結合してテスト
  })
})
```

### カテゴリ
本プロジェクトの結合テストは、依存関係により分類：

| カテゴリ | 件数 | 実行状態 | 説明 |
|:---------|-----:|---------:|:-----|
| **PostgreSQL不要** | 58件 | ✅ 実行済 | DB不要で実行可能 |
| **PostgreSQL依存** | 78件 | ⏸️ 未実行 | DB環境が必要 |
| **Java依存** | 10件 | 📝 未実装 | Java環境が必要 |

## 2. 総合テスト (System Test)

### 定義
システム全体を**総合的に**検証し、エンドユーザーの視点から機能・性能・セキュリティを確認するテスト。

### 英語表記
**System Test** または **End-to-End (E2E) Test**

### 対象範囲
- システム全体の動作
- ユーザーシナリオに基づく一連の操作
- フロントエンド〜バックエンド〜データベースの全レイヤー
- 非機能要件（性能、セキュリティ、可用性）

### 実装例（将来的に）
- Playwright / Selenium などのE2Eテストツール
- ユーザーストーリーベースのシナリオテスト

### ユーザーシナリオ例
```
シナリオ: ユーザーが whereabouts を更新する

1. ユーザーがログイン画面にアクセス
2. accountId/password を入力してログイン
3. JWT トークンを取得
4. whereabouts 更新APIを呼び出し
5. データベースに正しく保存されたことを確認
6. 画面に更新結果が表示される
```

### 注意
**現時点（2025-11-07）では、本プロジェクトに総合テストは実装されていません。**
将来的に、E2Eテストフレームワークを導入する際に使用する用語です。

## 3. 用語の使い分け

### ❌ 避けるべき表現
- 「統合テスト」（Integration Testの訳として使用しない）
- 「結合」と「総合」の混在使用

### ✅ 推奨される表現

| 状況 | 使用する用語 | 英語 |
|:-----|:------------|:-----|
| 複数モジュールの連携テスト | **結合テスト** | Integration Test |
| システム全体のテスト | **総合テスト** | System Test / E2E Test |
| 単一モジュールのテスト | 単体テスト | Unit Test |
| 受入テスト | 受入テスト | Acceptance Test |

## 4. 歴史的経緯

### 用語統一前（〜2025-11-07）
以下のファイル名・内容で「統合テスト」が使用されていました：

```
❌ ref/PostgreSQL統合テスト実行ガイド.md
❌ ref/IT-023_Java_EncDec統合テスト実施ガイド.md
❌ ref/統合テスト状況サマリ.md
```

### 用語統一後（2025-11-07〜）
すべて「結合テスト」に変更されました：

```
✅ ref/PostgreSQL結合テスト実行ガイド.md
✅ ref/IT-023_Java_EncDec結合テスト実施ガイド.md
✅ ref/結合テスト状況サマリ.md
```

**理由**:
- 日本の開発現場で「結合テスト」が一般的
- 「結合」と「総合」の漢字が直感的に区別しやすい
- Integration = 結合（複数を結び合わせる）、System = 総合（全体を総合する）

## 8. よくある質問（FAQ）

### Q1: なぜ「統合テスト」ではなく「結合テスト」？
**A**: 将来的に System Test（総合テスト）を実装する際、「統合」と「総合」では混乱するため。「結合」なら明確に区別できます。

### Q2: 英語で書く場合は？
**A**: 英語では従来通り "Integration Test" を使用します。日本語訳として「結合テスト」を採用しています。

### Q3: 既存のドキュメントはどうする？
**A**: 2025-11-07 に全て「統合」→「結合」に変更済みです。今後は「結合」で統一してください。

### Q4: 「総合テスト」はいつ実装する？
**A**: 現時点では未定です。フロントエンドとの連携が必要になった際、Playwright等でE2Eテストを実装する予定です。
